# Лабораторная работа №3: Приём вторсырья

## Описание предметной области
REST API для управления пунктами приема вторсырья. Пользователи сдают мусор (создают партии), за что получают бонусные баллы. Система контролирует суточные лимиты пунктов приема.

## Схема базы данных (PostgreSQL)
- **users** — пользователи системы.
- **recycling_types** — виды вторсырья (цена в баллах за кг).
- **collection_points** — пункты приема (адрес, лимит массы).
- **point_accepted_types** — связь многие-ко-многим (какие виды принимает пункт).
- **recycling_batches** — партии сдачи.
- **bonus_entries** — бонусные записи.

Ограничения целостности (CHECK, FOREIGN KEY) заданы на уровне БД в `schema.sql`. Для приложения создан ограниченный пользователь `app_user` (только CRUD, без DDL).

## Реализованные бизнес-операции
1. **Приём партии** (`POST /api/business/accept-batch/{id}`) — проверяет суточный лимит пункта, меняет статус партии и начисляет баллы. Затрагивает 3 сущности.
2. **Отмена партии** (`POST /api/business/cancel-batch/{id}`) — отзывает баллы, если они не были потрачены. Затрагивает 2 сущности.
3. **Закрытие пункта** (`POST /api/business/close-point/{id}`) — запрещено, если есть непринятые партии. Затрагивает 2 сущности.
4. **Обмен баллов** (`POST /api/business/redeem-points/{userId}`) — возможен только при сумме >= 1000 баллов.
5. **Статистика** (`GET /api/business/statistics`) — отчет по массе сданного сырья.

## Запуск
1. Установить PostgreSQL.
2. Выполнить SQL из `schema.sql` (создание таблиц) и `data.sql` (тестовые данные).
3. Заполнить `.env` файл (URL, логин, пароль).
4. Запустить `Lab2Application`.
